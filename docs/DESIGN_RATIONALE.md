# Design decision record

The user delegated routine design decisions and asked for implementation to continue without a design approval pause. No incumbent LabelDesk visuals or brand assets were present. Impeccable's catalog rolls completed after a read-only retry; the project chose the assigned visual direction and the leading dealt composition.

## Seven visual systems considered

1. Change-control diff: aligns fields and exposes only what changed; strongest fit, with a familiar software-review risk.
2. Postal routing docket: shows who filed, reviewed, and received the record; useful for provenance but can overemphasize handoffs.
3. Scientific calibration log: ties a run to a fixed method and result; credible but risks implying laboratory measurement.
4. Copy-edit proof sheet: makes correction marks immediate; useful for the single changed label but too editorial for the full workflow.
5. Archive accession register: protects stable IDs and provenance; useful but risks implying a static collection.
6. Jet-age airline ticket wallet: fixed coupon fields, carbon-copy identifiers, route sequence, and a stamped final receipt; chosen because a support ticket is inspected as a bounded record, challenge history remains attached, and the receipt can be followed without a wallet connection.
7. Surveyor field book: makes boundaries and stable reference points explicit; useful for sample membership but suggests spatial data.

## Challengers assessed

- Emission-line rail: declined on audience identification and product clarity. Kept its redundant non-color state marks.
- Pocket timetable slide rack: declined on both axes. Kept fixed alignment for comparing repeated fields.
- Dense Japanese web modules: competitive on audience familiarity, weaker on product clarity. Retained only concise row metadata; full ticket text stays readable.
- Botanical sequence: declined on both axes. Kept a registered, same-scale comparison for a row across revisions.
- Vertical media feed: declined on both axes. Kept one selected row as the focal reading task while sibling rows remain addressable.
- Ticket wallet: assigned direction, not a challenger. Avoid crypto-wallet terminology in product copy.

## Seven surface structures considered

1. Diff-first release table with a row inspector.
2. Change timeline with each finding on its event.
3. Three sample coupons side by side under a release header.
4. Registered coupon wallet: stable row index at left, aligned revision fields across the center, and the selected ticket, rubric, and receipt in a fixed inspection lane. Chosen from the dealt surface structures.
5. Vertical release stack with a correction slip over the original.
6. Docket queue with challenge state as the navigation spine.
7. Buyer receipt ledger with the sample comparison above it.
